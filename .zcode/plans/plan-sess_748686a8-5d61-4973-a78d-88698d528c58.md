# Metamorph 架构重构计划

参考 scilink-agent 的分层架构 + 阿里云 Python 开发规范，将当前扁平的新结构升级为生产级分层架构。

## 具体重构步骤

### 步骤 1: 修复 Bug + 补充基础设施文件
- `api/__version__.py` — 定义 `__version__ = "0.1.0"`（当前 routes.py 导入失败）
- `llm/providers.py` — 从 `client.py` 提取 `PROVIDER_DEFAULTS`，解耦循环依赖（settings 和 cli 同时依赖）
- `memory/__init__.py` — 导出 user memory 相关函数
- `tools/utils.py` — 工具结果处理工具（截断、格式化为 scilink-agent 风格）

### 步骤 2: API 层重构
- 将 `routes.py` 拆分为 `v1/info.py`, `v1/runs.py`, `v1/tasks.py`
- 创建 `v1/__init__.py` 注册路由
- 将 ThreadingHTTPServer 请求分发逻辑移至 `router.py`
- `workers.py` 管理 daemon 线程生命周期
- `middleware.py` 统一异常处理和日志

### 步骤 3: Graph 层拆分
- `streaming.py` — 提取 `run_agent` 中的流式 chunk 解析逻辑
- `loop.py` — 提取 agent→tools→agent 主循环逻辑
- `agent.py` — 保留为高层入口，协调 streaming + loop

### 步骤 4: Memory 层独立
- 从 `tools/memory.py` 提取数据访问和格式化逻辑到 `memory/`
- `tools/memory.py` 变为薄 wrapper，仅保留 tool 注册

### 步骤 5: LLM 层扩展
- `providers.py` — 独立 PROVIDER_DEFAULTS
- `thinking.py` — thinking 配置（参考 scilink-agent thinking_config.py）

### 步骤 6: 工具层补充
- `utils.py` — `process_tool_result()` 等通用工具
- `__all_tools__.py` — 所有工具注册总览，含 display_name / category

### 步骤 7: pyproject.toml 更新
- 更新 packages.find include 列表
- 添加新包
- 修复 console script 入口

### 步骤 8: 测试更新
- 更新 `test_agent.py` 中的 import 路径
- 拆分 `test_tools.py`

### 步骤 9: 文档更新
- 更新 README.md 架构图
- 更新 ARCHITECTURE.md

## 参考 scilink-agent 的关键设计模式
1. **`api/v1/` 版本化路由** + 每个子路由独立文件
2. **`graphs/` 分层**: builder 构建图，main_graph 定义工具和图
3. **`llm/` 拆分**: reasoning_patch + thinking_config 独立
4. **`memory/` 独立层**: 多层记忆管理
5. **`tools/` 有 utils.py + retry.py**: 通用工具函数
6. **`scheduler/` 预留**: 自动化调度框架
7. **`state/` 独立状态**: agent_state + 注入队列

## 参考阿里云 Python 规范
1. 每个包有 `__init__.py` 并明确 `__all__`
2. 模块注释说明职责
3. 函数/类有 docstring
4. 常量用全大写
5. 类型标注全覆盖
6. 无循环依赖
7. 配置集中管理
