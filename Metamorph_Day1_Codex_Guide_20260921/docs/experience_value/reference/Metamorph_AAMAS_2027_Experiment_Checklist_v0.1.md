## 0. 研究卡片：本轮不再换题

**主问题：帮助 Agent 完成当前任务的执行结构，是否也帮助它产生对未见任务有用的经验？若存在差异，经验获取、整理和使用分别扮演什么角色？**

工作标题：*Do Execution Scaffolds Help Agents Learn? A Controlled Study of Transferable Experience*。

论文定位：冻结基础模型的系统级经验学习实证与机制研究。Metamorph 是实验载体，不声称实现 RSI、不声称更新了基础模型权重，不将四组对照或经验移植本身宣称为首次发明。

候选贡献（尚不是发现）：
- 区分练习期即时表现、系统内经验收益和共同接收者上的经验包价值。
- 控制经验来源、离线整理方式和接收者，检验流程影响的环节及适用边界。
- 给出可复核的条件性设计结论，而非预设固定流程或自主组织一定更好。

本轮不做：自动选课程、基础模型训练、模型/provider 动态路由、在线任意改写 harness、自动 DAG 搜索、多 Agent 扩张、真实外部账号操作。它们不是被否定，而是没有进入本轮主比较。

## 3. 三个 RQ 与预定估计量

### RQ1：执行方式是否改变系统内经验收益？

四组记为 F0、U0、F1、U1（0=跨任务不继承，1=继承）。

令 S 为同一确认测试集合上的平均原生任务分数：
- G_F = S(F1) - S(F0)
- G_U = S(U1) - S(U0)
- I = G_U - G_F

I 是本研究的交互对比，不是新算法；S、正确率与实际费用同时报告。保留方式改变后会影响后续经历，因此 I 是这些具体系统的整体处理效应，不能直接等同于某一个记忆部件的作用。

### RQ2：即时表现与经验包价值是否一致？

主要比较：同一个接收者 E* 使用 M_U 与 M_F，在同一批未见探针上的分数差。

V(M) = mean_score(E*, M) - mean_score(E*, empty)

Delta_V = V(M_U) - V(M_F)

E* 预先固定，与两种来源共用同一个基础模型、指令、工具、预算和初始环境。E* 不是“绝对中性”或最优接收者，结论是对所测试接收者的可用性。

同时计算源流程练习期表现 P_U - P_F，使用对应 F1/U1 来源的配对学习轨迹。只有两项差异的不确定性分析支持相反方向时，才声称可靠的排序反转；不能仅因点估计异号就宣称存在冲突。F0/U0 的即时差异单独报告，不与不同来源工作区混拼。

不使用仅两种总体配置的相关系数证明“执行表现不能预测学习”。若分析轨迹级关联，必须说明环境/任务难度等混杂，定位为探索性。

### RQ3：获取、整理与使用有哪些条件性作用？

E3/E4 通过受控输入、接收者和局部内容干预提供机制证据。它们不是严格自然中介分析，不把各实验效果强行加和解释 E1 总效应。

## 4. 四组的严格定义

| 条件 | 当前任务流程 | 每次新会话起始工作区 | 当前任务内能做什么 |
|---|---|---|---|
| F0 | 固定阶段 | 空 | 文字、代码、测试与临时产物均允许 |
| U0 | 自主安排 | 空 | 与 F0 相同原始能力 |
| F1 | 固定阶段 | 上次自生成工作区 | 读取、执行、修改、删除已有产物 |
| U1 | 自主安排 | 上次自生成工作区 | 与 F1 相同原始能力 |

### F：可复现但不故意低效的固定流程

同一会话、同一基础模型执行：检查任务/资料 → 实施方案 → 检查结果（必要时回到实施）→ 决定保留哪些成果。

只规定阶段组织，不要求固定篇幅、不要求每题长篇规划、不要求一定生成 lesson、不禁用合理重试；允许检查“不适用”或没有值得保存的内容。阶段共享实际历史，不偷偷做额外摘要。

在实现中记录流程服从率。若只是提示建议而没有程序保证顺序，论文必须写“预设流程提示”，不能称为程序强制的固定流程。正式比较前必须选定一种实现；不混用两种口径。

### U：方法组织自主，不等于增加资源/权限

与 F 相同工具和输出目标，Agent 自行决定检查、试验、实施、验证、整理的时机与顺序。允许自发采用有结构的方法，不强迫它“保持自由”。不允许调用未登记模型、绕过费用/工具计量、触碰隐藏评估器或真实外部账号。

### 共同不变量

- 同一个 backbone/API 版本及请求配置；无静默 fallback。
- 原始工具能力、文档、错误反馈、可见 task 输入、初始世界状态相同。
- 相同任务序列/任务顺序块、总预算上限、工具次数上限、上下文策略、CPU 时间限制。
- 相同产物载体与文件访问入口；不许 U 写代码而 F 只能写笔记。
- 相同目标说明：完成当前任务，也可以形成可复用成果；不单独鼓励 U 为未来投入。
- 继承开关由 runner 实施，不用不同奖励或额外学习提示暗中改变处理。
- 格式约束只保留工具/任务接口所需部分，不要求输出私有推理或大段内部 JSON。
- 提示、阶段切换和整理开销属于处理实际成本，不能不计。

## 5. 环境与数据

### 主环境候选：CL-Bench Database Exploration

来源 [S3] 的官方任务为 40 个问题，20 个在原数据库、20 个在迁移后；不能假设它有数百个独立数据库。选它是因为存在可通过交互发现并复用的数据库组织信息，不是因为它保证自主方法有优势。

首轮建议先用稳定状态任务，分离经验积累与状态漂移；任务划分、冻结探针和顺序若不同于官方 schedule，应明确为“基于 CL-Bench 任务的改编协议”，不冒充官方完整榜单结果。

主评分保存官方原生 reward，同时拆出答案正确率、查询次数、全部 token/API 成本。SQL 经统一代理计量；Agent 沙箱不直接挂载可绕过接口的数据库文件。脚本内部发起十个查询也应计十次。

### 外部复核候选：CL-Bench Codebase Adaptation

来源 [S3] 中仅含 19 个 issue、两个仓库。若采用，保留各 issue 原始 base commit 和隐藏回归测试隔离，跨题不继承已经修改过的代码仓库；只有显式经验工作区可继承。

不假定改编少量 issue 足以证明跨仓库普适性。接入超过开发期限就停止扩张，缩小结论范围，不把单领域结果宣传成通用规律。

### 数据分层与独立性

- 开发集：调试环境、提示、上限、任务准入与运行器。
- 机制探针：开发后冻结，用于预定交叉/局部干预。
- 确认测试：流程与分析冻结后使用，不反复回看调方法。
- 经验获取题与评估题不重复；检查模板、查询结构、问题实体与答案重合。
- 同一数据库上的新问题属于同环境迁移，不等于新数据库/新领域迁移。
- 同一题库的重排属于顺序/采样复核，不增加独立环境数量。
- 公布所有 ID、选择规则、原始版本和修改。不能只取成功获取到经验的学习序列。

开发阶段可用一份来自相同可见历史的人工参考记忆，检查任务是否有可利用的信息；它只是正控制，不能加入 U 组当作自主成果。所有任务也必须通过正常工具可解。

## 6. 跨会话信息通路与防泄漏

每次新任务强制建立新的模型会话。模型权重不变；禁止通过隐藏线程、聊天 history、自动摘要、环境缓存或未清空进程继承信息。

- `/memory`：本轮唯一允许跨任务传递的 Agent 自写产物。
- `/work`：当前任务 scratch/输出，每题重新初始化。
- 工具环境：固定的只读数据库或按 issue 重置的仓库；不能成为隐式记忆通道。
- researcher log：完整可见消息、实际工具事件、usage、产物变化；默认 Agent 不可读。
- hidden evaluator：独立权限/进程，Agent 及生成代码不可读取或修改。

不继承组的产物可由研究者归档，但后续 Agent 无法访问。继承组只加载自己此前的工作区；研究者不筛选、补写、人工修复。

每个探针从冻结工作区独立复制。探针中允许临时写入/正常工具交互，但任务结束后丢弃副本，不向其他探针回写；探针结果不给经验来源系统。

文件路径入口与目录展示规则一致。把整个目录自动塞给一组、要求另一组自己找文件，属于不公平实现。

## 7. E0：先验收，再付费扩展

无模型测试：
- [ ] F/U 用相同底层执行循环；唯一流程差异可审计。
- [ ] 每个新任务清空聊天记录、环境、scratch 与进程。
- [ ] retention=0 后 sentinel 不可读；retention=1 后可读。
- [ ] 探针不能回写学习快照；并发任务不可互读。
- [ ] 不能从 symlink、工具参数、trace 路径或数据文件旁读取隐藏答案。
- [ ] 所有底层查询/API/工具操作均计量；脚本不能绕过上限。
- [ ] 格式错误、预算耗尽、任务错误、基础设施故障分开记录。
- [ ] workdir snapshot 可重建；hash、版本和父 run 可追溯。

真实请求测试：
- [ ] 用当前正式候选模型检验短工具回路、保存、读取与结束。
- [ ] 保留真实 model 标识、请求配置、usage、响应终止字段（没有则记缺失）。
- [ ] 用开发实例测量平均成本、长尾成本与耗时；报告失败尝试费用。

小样本 protocol 全通过只是进入试跑的工程条件，不是统计稳定性保证。

## 8. E1：原生系统 2×2

每个独立学习 replicate 从空 memory 开始，四个条件共享相同练习序列与探针。组内不选最好 seed。

记录：练习期逐题分数与支出；空工作区、固定练习数（如第 2、6 题）后的快照；冻结探针分数。中途探针不得影响来源系统，成本单列为研究评估费用。

以终点快照作为主结果，不选过程峰值。零产物、无效产物、失败执行也是系统表现；不能排除后才比较。

输出：四组表、G_F/G_U/I、正确性/查询/费用分项、典型有效和有害继承案例。

## 9. E2：共同接收者（主要确认实验）

预先固定 E*。每个 F1/U1 配对学习 replicate 生成的快照进入以下条件：
1. EMPTY：不加载先前经验。
2. M_F：固定流程的自生成工作区。
3. M_U：自主流程的自生成工作区。
4. RAW_F：同一固定流程来源的可见原始经历。
5. RAW_U：同一自主流程来源的可见原始经历。

RAW 通过与 memory 相同的文件读取/检索入口访问，不附隐藏评分、正确答案或研究者诊断，不对来源轨迹挑优。RAW 是否超过存储/读取/上下文额度，以及预定截断规则须记录。原始回放不是理论上界。

主要比较 M_U vs M_F；次要比较各自 vs EMPTY/对应 RAW。EMPTY 可在条件完全相同的预定评估块内共享，但统计中不能把同一次 baseline 当成多次独立样本。

经验可包含可执行程序和文字；代码只在相同 sandbox/工具计量下执行。移植失败不能让研究者手修某一组；它是兼容性的一部分，需单独报告。

E* 的形式可能偏好某种产物，E5 中用另一种接收者复核。不得称共同接收者“绝对中性”。

## 10. E3：轨迹来源 × 离线整理方式

从 E1 的 F0/U0 原始经历取 T_F/T_U，避免已有持久工作区反馈反复卷入。采用预定的完整事件导出规则；导出不包括 evaluator 标签或研究者诊断。源模型曾在线整理的动作可能仍存在于轨迹中，应承认这不是对自然认知阶段的完美切割。

| 输入经历 | 固定整理 C_F | 自主整理 C_U |
|---|---|---|
| T_F | M_FF | M_FU |
| T_U | M_UF | M_UU |

每个整理器以同样空工作区开始；同模型、同整理预算、同工具/文件能力、同产物容量。整理阶段禁止重新查询原环境、查隐藏测试或获得新的外部证据；可分析给定日志并运行其数据上的本地计算。

全部产物交给 E*。对固定 T 比较整理器，对固定 C 比较经历来源。

若输入太长，开发时先确定所有条件共享的完整分块/检索规则，不能人为摘取“重要片段”。既报告固定获取预算下的自然轨迹，也用受限读取作为敏感性；不要事后把轨迹长度作为普通协变量就宣称排除了中介因素。

输出：交叉表、整理总费用、事实/技能证据的审计样本。解释为受控离线再整理实验，不强行解释线上 F1/U1 的全部差异。

## 11. E4：经验内容的局部干预

在预先分层选定的工作区/任务上比较：
- FULL：原始快照；
- ABLATED：移除指定可用信息或技能内容，尽量保持运行接口；
- RESTORED：恢复原始相同内容；
- SHAM：按同一操作流程处理，但不移除关键语义。

先检查依赖与重复副本，不删除 import 入口导致启动失败后宣称知识重要。恢复条件做重复执行；相同 hash 只保证恢复了文件，不保证随机模型必然生成同一轨迹。

选择规则在查看干预结果前冻结；不能只展示 U 的有效文件或 F 的错误文件。先盲标一部分：正确/错误、任务特异/可复用、有证据/无证据、是否被读取或执行。人类双人复核的小样本优于仅用同一个 LLM 自我评分。

额外无新增信息但有相同处理/推理机会的控制可用于排除“只是又想了一次”。不要将这种等调用诊断等同于总成本严格匹配。

## 12. E5–E6：外部性与稳健性

优先顺序：
1. 第二环境复核 E1/E2 的主要比较；若只有一个环境则收窄论文题目与外推。
2. 第二 backbone 从头产生经验并复核关键比较：这才支持跨执行模型结论。
3. 仅更换接收者、沿用原经验：支持产物兼容性，不等于整个学习过程跨模型泛化。
4. 一种合理的固定流程替代表述/实现，防止结果只源于一个弱提示。
5. 第二个预算点；完整计算阶段提示、查询、整理与检索成本。
6. 固定前缀长度/任务顺序复核，防止后半段题目变简单伪装成学习。
7. 如数据与资源许可，测试旧知识失效/新状态；单列漂移实验，不混同稳定世界主结果。

不开展所有因素的全笛卡尔积。每项选择基于预先列出的替代解释，不根据哪个图更好看。

## 13. 样本和费用：阶段性参考，不是录用门槛

开发试验：4 组 × 2 个配对学习 replicate ×（3 练习 + 3 探针）= 48 个完整任务回合。

开发 E2：2 个配对来源 × 5 个记忆条件 × 3 探针 = 30 个额外探针回合。

因此第一批目标为 78 回合（另有基础设施 smoke），不是“今天全部完成”。开发题和开发产物不进入正式主统计。

主领域的初步计算例：
- E1：8 个独立从零开始的配对学习 replicate × 4 组 ×（6 练习 + 8 探针）= 448 回合。
- E2：8 配对来源 × 5 记忆条件 × 8 探针 = 320 回合。
- 合计 768 回合，仅覆盖主领域 E1/E2，不包括 E3/E4、第二环境/模型、额外 checkpoint 和重跑。

这些是费用规划参数，不是假设现有题库有任意多独立任务，也不是统计充分性证明。以开发方差、可检测的最小有意义差异、题库结构、实际预算和耗时做样本规划，正式开跑前冻结。8 个采样 replicate 不等于 8 个独立数据库；同库重复只能支持给定环境上的随机/顺序稳健性。

费用公式：
总成本 = 经验获取 + 产物整理 + 测试读取/执行 + 额外机制评估 + 失败与重试。

分别报告系统使用成本和为研究而增加的评估成本；不能把后者藏掉，也不能把同一来源费用在同一总额里重复计数。提供所有尝试平均费用、总支出/正确任务数（明确为批次分摊值）、以及产物复用不同次数时的摊销分析。没有正确任务时不要除零或填零成本。

预算不足时优先减少次要维度，不能删掉 EMPTY/RAW、共同接收者或只保留优胜 seed。

## 14. 统计分析与失败口径

- 主效应：E2 的 Delta_V；E1 的 I 与 E3 为预先登记的次要/机制分析。
- 每个环境分别报告原生 reward、正确率、非预期副作用、协议有效性、输入/输出/cached token、LLM 调用、底层工具调用、CPU/墙钟时间、费用。
- 不将成功实例条件平均费用当作完整部署成本。[S5]
- 使用配对分析；重采样/区间计算保留独立学习 replicate、共享工作区与环境层的关联。多个探针不是多个独立学习系统。
- 对同题重复取平均 pass@1，不取“至少成功一次”代替可靠性。
- 主比较双侧区间/检验，允许任一方向；多个确认性比较使用预先确定的校正方式。
- 不显著不等于等价；若声称近似等价，应预定实际意义边界并检查区间是否足够窄。
- 行为错误、空产物、超预算、工具调用错误属于系统结果，不能删除。
- 基础设施中断单列；有限自动重试规则预先冻结，重试成本全部计入。主结果给保守口径，敏感性结果公开排除与重跑规则。
- 因实现缺陷导致的无效批次标为 invalid，修正后按相同规则重跑受影响配对；保留旧数据，不逐题挑最好结果。
- 测试集不可驱动新提示或选择峰值；追加未预定机制分析标 exploratory，需另有确认集才升格。
