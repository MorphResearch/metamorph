今天的 F 只是预设提示。因此：
- 报告 `fixed_workflow_implementation=prompt_prescribed_v0`。
- 保留可见行为供后续检查；语义服从率不能仅凭正则看见几个词就判定。无法可靠自动判断则记 `unknown/manual_review_pending`。
- 不因 F 未遵循提示就排除任务或重跑到遵循为止。
- 不为强制通过阶段检查而给 F 增加额外 LLM 调用。

## 4. 环境：先接现有候选，卡住则只做工程夹具

优先检查本地是否已有 CL-Bench Database Exploration。依据真实版本的 README/接口实现，记录源码 commit、任务 ID、环境版本与评估接口。不要把上一轮文档描述当成已安装事实。

只接入一个开发环境，不拉取/运行全部 benchmark、不引入新的付费服务。外部代码/数据获取遵守当前网络与安装权限；需要扩大权限就停在该步骤并报告，不绕过限制。

如果短时间内无法接通公共环境，记录具体异常，继续用一个最小 `local_fixture`：
- 只有非敏感合成数据的小型 SQLite 数据库。
- 一道练习和一道不同问题的探针；它们共享可发现的数据库关系，但答案不相同。
- 通过真实 SQLite 查询返回行、列和错误；fixture 不是预写成功回复。
- 研究者侧使用确定性参考计算核验任务可解性，不能把答案和参考查询提供给 Agent。
- fixture 的所有任务明确标为 `engineering_smoke`、`included_in_primary_analysis=false`，ID 使用本地前缀，绝不能伪装成官方任务 ID。

主环境未接通时，今天的环境接入状态只能写 BLOCKED/PARTIAL；夹具通过不能替代公共环境通过。

### 数据库必须经统一入口计量

原始数据库文件留在工具服务侧，不挂载到 Agent 文件系统。只暴露该任务必要的查询接口；计量入口统计成功、失败及脚本发起的每次底层查询。

只读数据库任务禁止借 ATTACH、扩展加载、任意文件函数或多语句等绕出允许范围。控制应由实际数据库权限/授权检查和工具服务实现，不能把字符串 contains 检查描述为完善隔离。

不要为证明记忆有效而禁止无记忆组正常重新查询；工具信息获取能力对所有条件相同。

## 5. 工作区与快照：本日最重要的实现

Agent 可见逻辑路径：`/memory` 与 `/work`。它们映射到本实验创建的隔离目录，不是要求在宿主机根目录创建或清空这些路径。

- `/memory`：唯一允许跨题继承的 Agent 自写产物。
- `/work`：当前题临时文件，每题从空目录重新创建。
- 当前题工具环境：按任务协议重建；不能留下前一题 SQL 临时表、连接状态或修改后的仓库。
- 研究日志、源快照、隐藏评分器和其他组目录：Agent 不可见。

每道题构造全新的模型消息列表/会话。禁用跨题 resume、隐藏线程、自动历史摘要与未清空 Python globals。运行器可复用连接池，但不能复用带任务内容的会话状态。

retention=0：下一题从新空 `/memory` 开始；旧产物由研究者侧归档，Agent 不可再读。

retention=1：只复制同一条件、同一 learning replicate 的上一练习快照。不读取其他组或其他 replicate。第一道题同样从空工作区开始。

探针：每题从冻结快照独立复制；内部可读写，结束后丢弃副本；不回写源快照，也不传给下一道探针。EMPTY 使用空快照。所有探针使用相同文件入口。

快照应可重建并有内容 hash：对规范化相对路径、文件类型/相关执行权限及内容生成 SHA-256；不要让 mtime 成为内容变化。拒绝越界链接/特殊文件，不用会共享写入的 hardlink 充当独立副本。记录来源 run、父快照与文件清单。

空快照是合法结果。不得因为 Agent 没写经验，就由 runner/Codex 人工代写、从聊天自动提取或悄悄创建技能。

## 6. 代码执行隔离：只使用真实边界

优先复用已有经过测试的隔离执行器；Agent 生成代码不在宿主研究进程内直接 exec，不继承宿主机密钥/家目录，不挂载完整仓库、Docker socket 或隐藏答案。

只读数据库工具服务和模型凭证留在 Agent 沙箱外。沙箱只允许必要的受控工具调用，不开放任意外网或额外模型调用。程序内部查询同样经计量接口。

Python 子进程、改 working directory、路径过滤、禁几个 import，不能单独被称为操作系统级沙箱。

若当前不存在合适隔离：继续跑受控文件/工具 mock 和单元测试，禁用任意代码执行，记录 `code_execution_isolation=BLOCKED`。不要临时搭一套大型安全平台，也不要降低权限边界来得到“通过”。缺失安全执行能力时，真实比较的可用产物范围要标清，不能宣称完成代码技能继承验证。

## 8. 费用与真实调用开关

默认所有命令离线。测试不得在 import、收集测试、读取配置或构造客户端时发起真实模型请求。

保留参考协议中的 `study.paid_batch_authorized=false`。另外通过独立本地授权文件控制单次 live smoke；不能因为找到 API key 或项目内某个旧脚本能调用，就认为已有新实验授权。

live 必须同时满足：
1. 研究者确认实际 provider/model、请求参数和要运行的开发 manifest。
2. 明确本次 smoke 的货币硬上限和货币单位、计价来源/更新时间；可保守使用未缓存价估算上界，缺报价或无法限制最大请求费用则阻断 live。
3. 本次 run_id、允许的最多 3 回合，以及请求数、token、工具数、超时/重试上限填实。
4. 实际隔离、无泄漏、停止与费用计量测试通过。

所有调用（包括重试）先登记并预留最坏情况下的支出，再发起。先串行执行；下一请求可能超过剩余额度就停止。请求返回后用真实 usage 结算，并标明 token 是否估算。供应商费用不能保证精确到账，但必须明确价格口径和预留规则。

usage、cache 或终止字段未提供就记 null/unknown，不能填成 0 或编造。发生超时但费用不确定，记 `billing_unknown`，保留预留并暂停下一真实请求等待核对，不自动无限重试。任务失败仍计费。

用户没有确认预算和模型时：完成其他步骤，在报告中给出需确认的最少字段；不得擅自设置授权为 true。

## 9. 必须实际运行的无模型验收

复用现有测试框架；无 pytest 时可以使用标准库测试，不为此大规模装包。默认拦截所有真实 provider 请求。至少覆盖下列行为，测试失败就记录并局部修复：

| ID | 验收行为 | 可检查的证据 |
|---|---|---|
| T01 | 同工具/同模型配置下，仅 F/U 流程提示有差异 | 提示 diff、工具 schema hash、请求配置 hash |
| T02 | 每题真正构建新会话 | 前题随机标记没有进入新题首请求、会话/进程状态重置 |
| T03 | retention=0 不可取回旧文件 | 从 Agent 实际工具入口读已知 sentinel 路径失败 |
| T04 | retention=1 能读取相同原始字节 | 实际工具读取与父快照 hash 一致 |
| T05 | 同一冻结源的两道 probe 不互相影响 | probe A 写入的新标记在 B 中不存在，父 hash 不变 |
| T06 | 条件/replicate 之间隔离 | 跨组路径、相邻目录及 symlink 读取被拒绝 |
| T07 | 隐藏评估器/日志/原始数据库不能从 Agent 访问 | 从运行时工具与沙箱路径实际尝试，不只测试 helper |
| T08 | 所有底层查询计量 | 成功、失败与脚本循环查询均进入计数；超限前阻断 |
| T09 | 未授权 live 永不调用 provider | spy/mock 断言真实调用数为零；缺参数立即可解释报错 |
| T10 | 预算边界和请求失败正确处理 | 预留→结算；达到上限停止；超时账单未知暂停 |
| T11 | 空产物不被补写，错误类型不混淆 | 空快照、错误答案、工具错误、超时分别保留 |
| T12 | RAW 不携带评估侧内容 | 独有隐藏 canary 未出现在 RAW、prompt 或工作区 |
| T13 | 快照独立、重复运行不覆盖 | 字节/文件清单重建，修改副本不改变源；attempt ID 不同 |
| T14 | E2 五种来源可注入且 receiver 保持一致 | source provenance、固定 receiver hash、独立 probe 目录 |

工具及 Agent 看见的是被测运行时边界；单测中测试进程本身读不到/读得到文件并不是同一件事。报告每项真实测试命令、exit code、断言结果及证据位置。

T03/T04 可使用随机 sentinel 和 ScriptedAgent。这只证明 plumbing，不证明 LLM 自主生成知识。

不能执行的测试记 BLOCKED，不许用 skip 后总绿灯写“全部通过”。单个本地安全测试通过也不等于证明沙箱不存在漏洞。

## 10. 真实微测试：满足授权才执行，最多 3 回合

预先固定一个开发练习 P 和不同问题的开发探针 Q。来源默认 U1，只为验收通路；这不是 F/U 效果比较。

1. **practice_source**：从空工作区，用真实被测模型在 P 上查询/执行，并可自行创建产物。Codex 不代做任务、不手写被测记忆、不把本任务书塞给被测 Agent。
2. **probe_with_memory**：结束 P 的会话，冻结工作区。创建全新 receiver 会话，在独立副本上执行 Q。
3. **probe_empty**：同一 receiver、同一 Q、同一初始环境和预算，但工作区为空，独立执行。

在 manifest 中预先记录 probe 顺序，不按哪个结果好决定次序/seed。三个回合都标 `engineering_smoke`、`included_in_primary_analysis=false`。没有授权追加，就不自动重做整题。

报告实际：
- 是否创建了自写产物，内容来自哪个可见工具反馈？
- 新会话是否通过真实文件入口读取或执行了它？
- 空工作区分支是否无法读取上一题文件（但仍可正常重新查询）？
- 两个 probe 是否互不回写、费用和终态是否完整记录？

如果 P 没有生成产物，记 `NO_ARTIFACT_OBSERVED`，不补写、不反复更换任务直到出现。若产物存在但 Q 没读，记 `NOT_CONSUMED`；读取只证明接触，不能称为因果上必需。Q 无记忆也答对是允许结果，不通过禁止查询来强迫差异。

无 live 授权时，完成 ScriptedAgent 端到端链路并把真实部分标 `NOT_RUN_AUTHORIZATION_REQUIRED`。二者必须分目录/记录来源，不能把脚本预置的行为写成模型学到了。

## 11. 记录、可追溯性与后续批次计划

每个 run 在执行前登记 planned/start，结束时追加终态；异常中断留下 partial，不伪装 completed。

复用原协议字段，至少可重建：
- experiment/run/attempt、parent、paired block、learning replicate。
- environment/task/split/order、condition、phase、是否进入主分析。
- provider、requested/returned model ID、可用 seed、实际 request/prompt/tool schema hash。
- code commit；工作区有未提交修改时另存本次补丁/相关代码 hash，commit 本身不够。
- input/output snapshot hash、来源产物文件和实际读/执行事件。
- 每次调用的 input/output/cached/其他供应商 usage 字段、价格依据、预留与实际估算支出。
- 原生 reward、task_correct、protocol_status、infra_status、stop_reason、retry、运行时长。

task_correct / protocol_status / infra_status 各自独立，无法判断记 null/unknown。若 fixture 评分与公共环境不同，明确 evaluator_kind。禁止生成没有测量依据的成功率/节约百分比。

保留 Agent 可见消息和实际事件，不要求输出未公开的模型思维链。凭证和授权头必须脱敏；关键任务字段与反馈不可为了好看删掉。

创建一个 `plan-only` 或等效 dry-run：能列出后续 E1 48 回合与 E2 30 回合的依赖，但不发请求、不运行任务、不把 planned 行当结果。E2 来源必须指向对应 F1/U1 的未来快照，缺少来源时不能偷偷用空目录替代。

## 13. 验收报告与停止条件

生成 `DAY1_REPORT.md`，首页按以下格式报告：

```text
Repository preflight: PASS / PARTIAL / BLOCKED
Protocol draft: PASS / PARTIAL / BLOCKED
Offline tests: passed=?, failed=?, blocked=?
Scripted memory plumbing: PASS / FAIL / NOT_RUN
Real model smoke: PASS / PARTIAL / NOT_RUN / BLOCKED
Public benchmark integration: PASS / PARTIAL / NOT_RUN / BLOCKED
Memory generated / read / executed: 真实数量或 NOT_MEASURED
Agent-model requests / spend: 真实数值或 NOT_RUN/UNKNOWN
Paid batch launched: NO
Scientific improvement claim: NOT_EVALUATED
Ready for authorized development batch: YES / NO + blockers
```

报告正文包括：
1. 实际新增/修改文件与为什么需要。
2. 原系统哪些能力被复用，哪些没接通。
3. 测试命令、exit code、失败原因、证据文件位置。
4. 一个脚本化通路例子，及真实微测是否完成；两者分开。
5. 配置、提示、工作区和代码版本/hash。
6. 每项待确认问题，只询问本地代码和配置确实无法确定的最小集合。
7. 下一次允许做什么，以及具体可执行命令；不能自行启动下一批。

出现下列情况立即停止对应 live 步骤，但继续整理已有日志和可完成的离线工作：
- 预算/单价/请求上限/模型身份未确认。
- 工作区或隐藏评估器发生信息泄漏。
- 需要放大权限或裸机执行不受限代码。
- usage/账单未知导致不能继续控制费用。
- 重复的同类协议/基础设施错误，已经达到配置中的有限重试上限。
- 唯一可行修复需要重构全局 controller 或更换研究问题。

**今天的成功标准：有真正可运行、可测试的最小经验通路，并知道哪些部分已经验证、哪些还没有。不是自主组获胜，不是全部代码无条件打勾，更不是写出一份宣称自进化成功的报告。**
