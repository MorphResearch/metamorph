# 记忆与会话连续性实现记录

**日期**: 2026-08-25
**问题**: 用户反馈"没有记忆能力" + "一个问题就新开对话框"

## 根因分析

| 问题 | 根因 |
|------|------|
| 没有记忆能力 | `update_user_memory` 工具存在但 Agent 从不主动调用；`user_memories.jsonl` 永远为空 |
| 新对话框 | API 层无 `conversation_id` 概念，每次 POST 都是独立会话，历史消息不传递 |

## 修改文件清单

### 1. `state/store.py` — SQLite 表结构扩展

**新增表**:
```sql
CREATE TABLE conversation_messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    conversation_id TEXT NOT NULL,
    role TEXT NOT NULL,            -- 'user' | 'assistant'
    content TEXT NOT NULL,
    created_at TEXT NOT NULL
)
```

**`runs` 表新增列**: `conversation_id TEXT NOT NULL`

**新增方法**:
| 方法 | 说明 |
|------|------|
| `create(task, workspace, conversation_id=None)` | 返回 `(run_id, conversation_id)` 元组 |
| `get_conversation(conv_id)` | 按时间升序返回历史消息列表 |
| `append_message(conv_id, role, content)` | 追加单条消息 |
| `delete_conversation(conv_id)` | 删除整个会话及其 runs |

### 2. `graphs/loop.py` — `_build_conversation` 支持历史

```python
def _build_conversation(messages, data_dir, history=None):
    convo = [system_prompt]
    if history:
        convo.extend(history)   # 历史消息插入 system 之后
    convo.extend(messages)       # 最新 user turn
    return convo
```

### 3. `graphs/agent.py` — `run_agent` 新增 `history` 参数

将 `history` 透传给 `_build_conversation`。

### 4. `api/workers.py` — 核心串联

**`submit(task, workspace, conversation_id=None)`**:
1. 调用 `store.create()` 拿到 `(run_id, conv_id)`
2. 若 `conv_id` 已存在，读取 `store.get_conversation(conv_id)` 作为 `history`
3. 启动 worker 线程，传入 `history`

**`_run()` 完成时**:
- `store.append_message(conv_id, "user", task)` — 记录用户输入
- `store.append_message(conv_id, "assistant", answer)` — 记录 AI 回答

### 5. `api/v1/tasks.py` — 解析 `conversation_id`

```python
conversation_id = payload.get("conversation_id")
run_id, conv_id = worker.submit(task, workspace, conversation_id=conversation_id)
# 响应: {run_id, conversation_id, status: "queued"}
```

**API 使用方式**:
```bash
# 新建对话
POST /v1/tasks {"task": "你好，我是张三"}
# 响应: {"run_id": "abc123", "conversation_id": "xyz789", ...}

# 同一对话后续消息
POST /v1/tasks {"task": "我喜欢 Python", "conversation_id": "xyz789"}
```

### 6. `prompts/system_prompt.py` — 强化记忆写入指引

将 `update_user_memory` 的描述从"当你学到信息时"改为**"几乎每次对话都应该考虑调用"**，并明确列举触发场景（姓名、偏好、项目、技术栈）。

### 7. `tests/test_agent.py` — 新增 2 个测试

- `test_conversation_history`: 验证 append + get 基本流程
- `test_conversation_continuity`: 验证相同 `conversation_id` 的续写场景

## 记忆 vs 会话历史 — 概念区分

| 特性 | 会话历史 (conversation_messages) | 长期记忆 (user_memories.jsonl) |
|------|------|------|
| 存储 | SQLite | JSONL 文件 |
| 范围 | 单会话内上下文 | 跨会话用户偏好 |
| 写入方式 | Agent 自动（API 层 append） | Agent 调用 `update_user_memory` 工具 |
| 持久性 | 可选（可 `delete_conversation`） | 永久，除非主动删除 |
| 用途 | 让模型知道"刚才说了什么" | 让模型知道"用户是谁" |
