# Engineering log — 2026-08-22

## Objective

Establish a realistic local deployment plan for Metamorph on the user's Mac and define how the system can later be called from a frontend and evolved without losing safety or reproducibility.

## Environment inspected

- Repository: `Metamorph`
- Git branch: `master`
- Git remote: `https://github.com/MorphResearch/metamorph.git`
- Mac model: `MacBookPro18,3`
- Chip: Apple M1 Pro, 8 cores
- Installed RAM: 16 GB
- Storage: 512 GB-class disk; `df` reports 69 GiB currently free on `/`

## Decisions

1. No rented server is needed for v0.1. The Mac can run the API, control plane, SQLite, artifacts, and bounded workers.
2. Use a hosted model first. The recommended default is a balanced model, with a stronger model reserved for difficult evolution diagnosis and a cheaper model for routing and gates.
3. Keep the model provider behind a `ModelAdapter` interface.
4. Put the frontend behind a thin FastAPI backend. The browser never receives the model-provider API key.
5. Separate immutable safety/evaluation control-plane code from mutable prompts, skills, memory policies, and tools.
6. Treat candidate evolution as an offline or staged workflow: propose → test → benchmark → approve → promote or rollback.
7. Delay vector databases, automatic tool creation, multi-agent orchestration, and meta-evolution until the single-agent baseline is measurable.

## Why these decisions

The repository currently contains only a README, so the immediate deliverable is a trustworthy v0.1 design baseline rather than a claim that a runtime already exists. The hardware is adequate for orchestration but not a good target for hosting large models or many concurrent local workers. API-first also makes model comparison and later provider changes easier.

## Open risks

- evaluator quality can be worse than agent quality and create false improvements;
- memory can cause negative transfer or retain sensitive information;
- generated tools can pass unit tests while violating permissions;
- a 16 GB Mac should not run several large local models simultaneously;
- API cost, rate limits, and model behavior can change over time.

## Definition of done for the next milestone

One local task can be submitted through the API, executed in a bounded workspace, observed through structured events, evaluated with deterministic checks, and reproduced from its configuration and artifact manifest.
