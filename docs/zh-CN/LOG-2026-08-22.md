# 工程日志 — 2026-08-22

## 目标

为 Metamorph 在用户 Mac 上的本地部署建立现实可行的方案，并定义系统未来如何通过前端调用、如何在不牺牲安全性和可复现性的前提下持续演进。

## 检查到的环境

- 仓库：`Metamorph`
- Git 分支：`master`
- Git 远程：`https://github.com/MorphResearch/metamorph.git`
- Mac 型号：`MacBookPro18,3`
- 芯片：Apple M1 Pro，8 核
- 已安装内存：16 GB
- 存储：512 GB 级别磁盘；`df` 显示 `/` 当前约有 69 GiB 可用

## 今日决策

1. v0.1 不需要租服务器。本机可以运行 API、控制面、SQLite、产物存储和受限 worker。
2. 第一阶段使用托管模型。默认使用平衡型模型，复杂 evolution 诊断时使用更强模型，路由和 gate 使用更便宜的模型。
3. 通过 `ModelAdapter` 接口隔离模型供应商。
4. 前端放在轻量 FastAPI 后端之后，浏览器永远不接触模型供应商 API key。
5. 将不可变的安全/评估控制面与可变的 prompt、skills、memory policy 和 tools 分离。
6. 将 candidate evolution 作为离线或 staged 流程：提议 → 测试 → benchmark → 批准 → 晋级或回滚。
7. 在单 Agent baseline 可测量之前，暂缓向量数据库、自动 tool creation、multi-agent 和 meta-evolution。

## 决策原因

当前仓库只有 README，因此本次交付的重点是建立可信的 v0.1 设计基线，而不是假装 runtime 已经完成。这台 Mac 足以运行编排和控制服务，但不适合同时托管大型模型或运行大量本地 worker。API-first 也更方便后续比较模型和更换供应商。

## 下一阶段实现任务

1. 增加 Python 项目元数据和类型化配置。
2. 实现只读 runtime 和结构化事件日志。
3. 增加专用 workspace 沙箱以及命令/路径策略。
4. 为代码仓库任务建立小型确定性 benchmark。
5. 实现 evaluator 和 Run Manifest。
6. 增加 FastAPI task/status API。
7. 增加只读 episodic memory 和检索 A/B 测试。
8. 增加需要人工批准的 prompt/skill candidate evolution。

## 当前风险

- evaluator 质量可能低于 Agent 质量，从而制造虚假的改进；
- memory 可能造成负迁移，或保留敏感信息；
- 自动生成的工具可能通过单元测试但违反权限；
- 16 GB Mac 不应同时运行多个大型本地模型；
- API 成本、限额和模型行为会随时间变化。

## 下一里程碑的完成标准

用户可以通过 API 提交一个本地任务；任务在受限 workspace 中执行；过程通过结构化事件可观察；结果通过确定性检查评估；并且可以利用配置和产物清单复现这次运行。
