# 基于任务形态的多 Agent 架构

## 目标

第一版多 Agent 层把一个任务转换成可检查的执行图。它不会自动改写 Python 代码，也不会自动授予新的权限。

```text
任务
  ↓
任务形态分析
  ↓
角色/依赖关系设计
  ↓
角色 Agent 按依赖执行，并接收明确的上游上下文
  ↓
Lesson 交流
  ↓
贡献评估 Agent
  ↓
可审查的下一轮架构建议
```

## 组件

| 组件 | 位置 | 职责 |
|---|---|---|
| 任务形态分类器 | `multiagent/morphology.py` | 判断任务类型、复杂度、可分解性、依赖、核验需求和工具强度 |
| 架构规划器 | `multiagent/planner.py` | 选择受限角色并建立明确依赖 |
| 编排器 | `multiagent/orchestrator.py` | 按依赖运行角色并汇总最终答案 |
| Lesson 存储 | `multiagent/lessons.py` | 将 lesson 持久化到 `.metamorph/multiagent_lessons.jsonl` |
| 贡献评估器 | `multiagent/evaluator.py` | 测量边际贡献、纠错、独特性、冗余和信息有用性 |
| 调整策略 | `multiagent/evaluator.py` | 建议保留、合并、移除或新增角色；默认需要人工批准 |

## 当前角色模板

- 编程：分析 → 实现 → 测试 → 汇总
- 研究：检索 → 批判 → 汇总
- 规划：拆解 → 执行 → 风险审查 → 汇总
- 其他需要核验的任务：分析 → 核验 → 汇总
- 简单任务：执行 → 汇总

规划器会在每次运行中记录任务形态和最近 lesson。未来可以把确定性规划器替换成 LLM 规划器，但应保持 `ArchitecturePlan` 接口，并与当前 baseline 做对比。

## 当前贡献信号

确定性评估器是 baseline，不代表已经完成严格的因果识别。它使用以下可观测代理指标：

- 边际贡献：成功输出、独特性和纠错信号；
- 错误纠正：是否出现验证、不一致、风险或错误信号；
- 独特性：与其他 Agent 输出的距离；
- 冗余：与另一个输出的最大词汇重合度；
- 信息有用性：上游上下文与下游回答之间的联系。

评估 Agent 会提供结构化的第二意见。如果评估 Agent 没有返回合法 JSON，运行不会失败，确定性报告仍会保留。

## 证据与安全

每次多 Agent 运行都会记录架构、角色输出、贡献评估、lesson 交流和调整建议。Lesson 会持久化，但架构调整会标记为 `requires_human_approval`。自动改代码、执行 shell、改变权限和安装工具不属于第一版能力。

## 后续研究步骤

1. 用受控干预替换词汇代理指标：移除一个角色、屏蔽一条消息、合并两个角色，再用相同任务种子重跑；
2. 加入任务成功率和成本指标，避免只根据文本重合度推断贡献；
3. 比较单 Agent、固定多 Agent 和基于任务形态的自适应架构；
4. 增加审批命令，只晋级有证据支持的架构 candidate；
5. 使用 lesson 提议下一轮方案，但不静默强制改变系统。
